# Plan: FlowSnag MVP

*Version 0.1 · 22.11.2026 · based on [spec.md](spec.md) v0.5 (working name in the spec: Process X-ray)*

## Architecture

A static single-page app. No backend, no database. Everything the user loads is analysed in their browser.

```
 sources                     core (pure TypeScript, unit-tested)          UI (React)
 ─────────                   ────────────────────────────────────          ──────────
 CSV file / paste  ──┐       csv.ts      parse, guess columns, dates      ImportScreen
 GitHub REST/GraphQL ┼──▶    XrayEvent[] (case, activity, time, attrs) ─▶  MappingStep
 demo generator     ─┘       analyze.ts  cases, DFG, variants, rework,     AnalysisView
 (later: Jira OAuth, XES)                cycle time, 3 insights             ProcessMap (dagre + SVG)
                             worker.ts   runs analyze() in a Web Worker
```

* **Event format:** `xray-log` from [concept.md §3.1](concept.md): `case_id, activity, timestamp, [resource], [any attribute]`.
* **Map:** directly-follows graph with virtual start/end. Layout with `@dagrejs/dagre`, drawn as SVG (exportable later).
* **Detail slider:** a step or path stays on the map if at least `(1 − detail) / 2` of cases use it, plus each node's strongest in/out edge so the map never falls apart. At 80% that is 10% of cases.
* **Return (rework):** a move to a step whose first visit in this case was earlier than the current step's first visit.
* **Insights:** (1) the step with the most total waiting time, (2) the most common return, (3) the most bypassed of the steps most cases pass through; fallback: how much the top 5 paths cover.
* **Percentiles:** linear interpolation, same as numpy / PM4Py.
* **Timestamps without a zone are read as UTC** so results never depend on the viewer's time zone.

## Stack (ADR 0001)

TypeScript, Vite, React, Papa Parse, dagre, Vitest, Playwright. Hosting: Cloudflare Pages (free `*.pages.dev`). See [docs/adr/0001-static-app-stack.md](../../docs/adr/0001-static-app-stack.md).

## GitHub connector

| Mode | API | Requests | Limit |
|---|---|---|---|
| No token | REST: `GET /repos/{o}/{r}/pulls` + `GET /issues/{n}/timeline` per PR | 1 + N | 60/h per IP → about 50 PRs |
| Token (read-only, stays in the tab) | GraphQL: 50 PRs with timeline per request | N / 50 | 5,000/h → up to 500 PRs |

Activities: Opened / Opened as draft → Ready for review → Review requested → Changes requested / Approved → Merged / Closed without merge (+ Reopened, Converted to draft). Repeated steps in a row are collapsed; a merged PR's simultaneous "closed" event is dropped.

Pre-built demos of popular repositories are generated by `scripts/build-github-demo.mjs` (GitHub Action "Build GitHub demo data") and served as static CSV, so visitors don't spend their quota.
