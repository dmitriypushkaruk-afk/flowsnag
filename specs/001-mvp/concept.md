# Process X-ray: концепція з конекторами

Версія 0.1 · 22.11.2026 · технічна концепція. Продуктова специфікація (проблема, сценарії, попит, монетизація): [spec.md](spec.md)

Позначки: ✅ знаю напевно з документації API, 🔸 моя оцінка або треба перевірити перед реалізацією.

---

## 0. Коротко

- **Що це.** Безкоштовний візуальний «рентген» процесу в браузері: підключаєш Jira (або кидаєш файл) і за хвилину бачиш, як задачі насправді ходять по статусах, де застрягають і скільки повертаються назад.
- **Головне ядро** це один стандартний формат подій (event log). Усі конектори лише перетворюють свої дані в нього, а аналітика й візуалізація працюють тільки з ним.
- **Перший конектор: Jira Cloud.** Найкраща якість історії (changelog), найбільша аудиторія, і це твоє поле.
- **«Без бекенда» тримається, з одним чесним застереженням.** Обчислення й дані завжди в браузері. Для Jira кнопка «Підключити Jira» (OAuth 3LO) працює з браузера: запити до `api.atlassian.com` дозволені CORS ✅, але обмін коду на токен вимагає секрету (PKCE не підтримується ✅), тому потрібна **одна крихітна функція обміну токена без зберігання**. Дані задач ідуть браузер ↔ Atlassian напряму. Паралельно **CLI** для великих вигрузок і Jira Data Center. Деталі: [jira-api.md](jira-api.md). GitLab/Linear підключаються прямо з браузера.
- **MCP** корисний як другий канал: «попроси Claude проаналізувати процес у твоїй Jira». Але це не заміна веб-застосунку, бо MCP працює всередині AI-клієнта, а не на сайті.

## 1. З яких систем можна тягнути історію

Для process mining потрібна не поточна картка задачі, а **журнал змін**: хто, коли, з якого стану в який. Нижче системи, де такий журнал доступний через API.

| # | Система | Що дає для аналізу | Якість історії | Підключення з браузера | Аудиторія | Пріоритет |
|---|---------|-------------------|----------------|------------------------|-----------|-----------|
| 1 | **Jira Cloud** | changelog статусів, виконавець, спринти, тип задачі | ✅ відмінна, кожен перехід із часом і автором | 🟡 OAuth 3LO: CORS на `api.atlassian.com` дозволено ✅, але обмін токена потребує секрету → одна функція обміну; API-токен на `*.atlassian.net` блокується CORS → CLI | величезна, PM/Dev/ITSM | **MVP** |
| 2 | **GitLab** (issues, MR) | resource state/label events, MR: створено → рев'ю → злито | ✅ добра | ✅ OAuth з PKCE і CORS підтримуються 🔸 | розробка, держсектор DE (self-hosted) | MVP+1 |
| 3 | **GitHub** (issues, PR) | timeline events: labeled, assigned, review_requested, merged | ✅ добра для PR, слабша для issues (статусу як такого немає, лише labels і Projects) | 🟡 API має CORS, але OAuth-обмін токена ні → Personal Access Token у браузері або проксі | розробники, open source | MVP+1 |
| 4 | **Linear** | історія issue (стан, виконавець, цикл) | ✅ добра (GraphQL `issueHistory`) | ✅ API-ключ або OAuth з PKCE 🔸 | стартапи, сучасні продуктові команди | MVP+1 |
| 5 | **Azure DevOps** | work item revisions/updates (`System.State`) | ✅ добра | 🟡 PAT, CORS 🔸 | корпорації на Microsoft-стеку | пізніше |
| 6 | **Trello** | actions: `updateCard:idList` (переміщення між колонками) | 🟡 середня, колонка ≈ статус | ✅ клієнтська авторизація токеном у браузері ✅ | малі команди, особисті дошки | пізніше, дешево зробити |
| 7 | **Asana** | stories задачі (переміщення між секціями, завершення) | 🟡 середня | ✅ OAuth з PKCE 🔸 | маркетинг, операції | пізніше |
| 8 | **Zendesk** | ticket audits / ticket events (статус, група, агент) | ✅ добра, класичний сервіс-процес | ❌ CORS закритий 🔸 → проксі/CLI | сервіс-деск, саппорт | пізніше |
| 9 | **ServiceNow** | sys_audit, task_sla, history set | ✅ відмінна, але корпоративна | ❌ CORS налаштовує адмін клієнта | великі корпорації, ITSM | лише через CSV/CLI |
| 10 | **Salesforce** | OpportunityFieldHistory, CaseHistory | ✅ добра (якщо history tracking увімкнено) | 🟡 CORS allowlist налаштовує адмін | продажі, сервіс | лише через CSV/CLI |
| 11 | **HubSpot / Pipedrive** | історія стадій угод (deal stage history) | 🟡 середня | 🔸 перевірити | малий бізнес, продажі | ідея на потім |
| 12 | **OpenText / Kofax / Camunda / SAP** | журнали workflow-рушіїв | ✅ найкраща, бо це рушій процесів | ❌ лише експорт або локальний агент | твій досвід | через шаблон CSV |

**Висновок.** На старті Jira (головна аудиторія й твій досвід), потім GitLab і Linear (працюють прямо з браузера, тобто найчистіша історія «без бекенда»), потім GitHub PR (популярне, добрий «вау» для розробників: «скільки PR чекає рев'ю»). Корпоративні системи (ServiceNow, Salesforce, OpenText) закриваємо **шаблоном CSV і локальним агентом**, а не прямим конектором.

**Неочевидні, але цікаві джерела для «вау»-демо:**
- Публічні репозиторії GitHub (наприклад, React, VS Code): «як насправді живе PR у великому open source». Даних багато, вони відкриті, без входу. Чудово для LinkedIn-поста.
- Публічні Jira великих open source проєктів (Apache, Atlassian Ecosystem JIRA): відкритий changelog без авторизації 🔸.
- Відкриті академічні логи BPI Challenge (Rabobank, лікарні, держсектор Нідерландів) як демо-набори.

## 2. Як підключатися: варіанти і чесно про «немає бекенда»

### 2.1 У чому проблема

Браузер не дає сайту `xray.example` звертатися до `твоя-компанія.atlassian.net`, якщо Atlassian цього явно не дозволив (політика CORS). Для Jira Cloud REST API з API-токеном це заборонено 🔸 (перевірити першим ділом у спайку). Крім того, вхід через OAuth для багатьох систем вимагає секрет застосунку, а секрет не можна тримати в коді сайту.

### 2.2 Варіанти

| Варіант | Як працює | Чи «без бекенда» | Плюси | Мінуси |
|---------|-----------|------------------|-------|--------|
| **A. Прямо з браузера** | OAuth PKCE або токен, запити з вкладки | ✅ повністю | найпростіше для користувача | працює лише для GitLab, Linear, Trello, Asana, GitHub (PAT) 🔸 |
| **B. Розширення браузера** (Chrome/Firefox) | розширення має дозвіл на `*.atlassian.net`, бере історію використовуючи вже відкриту сесію користувача і передає її на сторінку X-ray | ✅ повністю, жодного сервера | не треба токенів, працює і з Jira Server/Data Center у корпоративній мережі; дані ніколи не йдуть третім особам | треба встановити розширення; публікація в Chrome Web Store |
| **C. Локальна CLI-утиліта** `npx process-xray export jira` | тягне історію з API на машині користувача і пише файл event log; далі файл кидаєш у браузер | ✅ повністю | максимальна довіра корпоративної безпеки, відкритий код, працює з будь-чим (ServiceNow, SQL-база, OpenText) | для технічних людей |
| **D. Прохідний проксі** (Cloudflare Worker) | сторінка ходить в API через тонкий проксі, який лише додає CORS-заголовки і нічого не логує | 🟡 сервер є, але без бази й зберігання | найзручніше: вставив токен і побачив | треба довіряти, що проксі не зберігає; токен проходить через твою інфраструктуру; корпоративна безпека такого не любить |
| **E. MCP-сервер** | локальний MCP для Claude Desktop/Claude Code: «покажи, де застрягають задачі в проєкті ABC» | ✅ дані йдуть лише в AI-клієнт користувача | модно, легко показати, AI сам пояснює вузькі місця | це інший продукт: живе в чаті, а не на сайті; аудиторія вужча |

### 2.3 Рекомендація

1. **Оновлено після аналізу Jira API ([jira-api.md](jira-api.md)).** Для Jira в MVP: **кнопка OAuth 3LO у браузері + одна безстанова функція обміну токена** (варіант D у мінімальному вигляді: проксі лише для обміну коду на токен, дані задач через нього не йдуть) і **паралельно CLI (C)** для великих вигрузок і Data Center. Застереження: з 2 березня 2026 OAuth/Forge-застосунки ділять глобальну квоту 65 тис. балів/год на всіх клієнтів, доки Atlassian не дасть квоту на кожного; трафік CLI з API-токеном під це не підпадає ✅. Розширення браузера (B) лишається запасним варіантом.
2. **Для GitLab, Linear, Trello: варіант A.** Тут обіцянка тримається ідеально навіть без розширення.
3. **Варіант D не робити на старті.** Він ламає головне повідомлення продукту. Якщо колись знадобиться зручність, то зробити проксі відкритим кодом, який можна розгорнути у себе.
4. **MCP (E) як другий етап і окремий канал видимості.** Той самий код конектора, загорнутий у MCP: інструменти `get_event_log(project, jql)` і `analyze_process(...)`. Бонус: MCP може віддати посилання на X-ray, де дані передаються у фрагменті URL (`#data=...`, фрагмент не потрапляє на сервер), і в браузері одразу відкривається карта процесу.

**Ключова архітектурна ідея:** конектор це чиста функція «API системи → event log», написана один раз на TypeScript. Вона запускається у чотирьох обгортках: у вкладці (A), у розширенні (B), у CLI (C), у MCP (E).

### 2.4 Як чесно сформулювати обіцянку на сайті

> «Ваші дані обробляються лише у вашому браузері. У нас немає бази даних і сервера, який бачить ваші задачі. Конектори Jira працюють через відкрите розширення або утиліту на вашому комп'ютері: код відкритий, можна перевірити».

Чого **не** писати: «немає жодного сервера взагалі», якщо колись з'явиться проксі. Статичний хостинг сайту (Cloudflare Pages / GitHub Pages) нічого не бачить, тож це не порушує обіцянку.

## 3. Відкритий формат подій для будь-якої системи

Твоя ідея з «нашим API, куди корпоративна система передає інфо» правильна за суттю, але застосунок без бекенда не може **приймати** дані ззовні. Тому замість «API, на яке шлють» робимо **відкритий формат + кілька способів його доставити**.

### 3.1 Формат `xray-log` (мінімум 3 обов'язкові поля)

CSV (або JSON Lines), кодування UTF-8:

```csv
case_id,activity,timestamp,resource,case_type
INV-1001,Отримано,2026-03-02T09:14:00Z,system,invoice
INV-1001,Перевірка бухгалтером,2026-03-02T11:40:00Z,o.koval,invoice
INV-1001,Погодження керівником,2026-03-04T16:05:00Z,m.schmidt,invoice
INV-1001,Оплачено,2026-03-06T08:00:00Z,SAP,invoice
```

| Поле | Обов'язкове | Значення |
|------|-------------|----------|
| `case_id` | ✅ | ID кейсу (задача, рахунок, заявка) |
| `activity` | ✅ | крок або статус, в який перейшли |
| `timestamp` | ✅ | ISO 8601 з часовою зоною |
| `resource` | ні | хто виконав (людина, група, система) |
| будь-які інші колонки | ні | атрибути кейсу для фільтрів (тип, пріоритет, відділ, сума) |

Сумісність: імпорт і експорт у **XES** (стандарт IEEE для process mining, його читають ProM, Disco, Celonis) і, пізніше, **OCEL 2.0** (об'єктно-орієнтований лог). Це робить інструмент «своїм» для професійної спільноти. Ручне зіставлення колонок для будь-якого іншого CSV лишається.

### 3.2 Як доставити дані з корпоративної системи без нашого бекенда

| Спосіб | Для кого | Як |
|--------|----------|----|
| **Файл (drag & drop)** | усі | вивантажив SQL-запитом або звітом у CSV і кинув у вікно |
| **Вставити з буфера** | аналітики | скопіював таблицю з Excel або результат SQL і вставив |
| **Посилання з даними у фрагменті** | невеликі логи, інтеграції | `xray.example/#log=<стиснутий base64>`; фрагмент після `#` браузер не надсилає на сервер |
| **`postMessage` з корпоративного порталу** | внутрішні розробники | їхній портал відкриває X-ray у новій вкладці і передає лог JavaScript-повідомленням; дані йдуть із вкладки у вкладку |
| **Вбудовування (iframe/віджет)** | внутрішні портали | npm-пакет `@process-xray/viewer`, який компанія вбудовує у свій інтранет; тоді дані взагалі не залишають їхній домен |
| **Локальний агент / CLI** | ІТ корпорацій | `process-xray export sql --query ...` або плагіни для ServiceNow, OpenText; на виході той самий `xray-log` |
| **Тека з автооновленням** | регулярні звіти | File System Access API: дав доступ до теки, де нічна вигрузка кладе файл, і дашборд оновлюється (лише Chromium) |

**Найцінніше для корпоративного світу**: вбудовуваний viewer + шаблон SQL-запитів для типових систем (OpenText Process Suite, Camunda `ACT_HI_ACTINST`, Kofax TotalAgility, SAP workflow `SWWLOGHIST` 🔸). Тут твій досвід дає реальну перевагу: ти знаєш, де в цих системах лежить історія.

## 4. Конкуренти і де місце безкоштовного візуального інструменту

| Гравець | Що це | Ціна і поріг входу | Чим ми відрізняємось |
|---------|-------|--------------------|----------------------|
| **Celonis** | лідер корпоративного process mining | шестизначні контракти, проєкт впровадження; є безкоштовний Academic/Snap-тариф 🔸 | ми: 0 налаштувань, дані не йдуть у хмару |
| **SAP Signavio, UiPath, Microsoft Power Automate Process Mining, IBM** | process mining у великих платформах | ліцензія платформи, хмара вендора | те саме |
| **Fluxicon Disco** | десктопний інструмент, улюблений консультантами | платна ліцензія, Windows/Mac, без конекторів | ми: у браузері, з конектором Jira «в один клік» |
| **ProM, PM4Py, bupaR** | академічні open source | потрібні Java/Python/R і знання методів | ми: без коду, для менеджера, а не дослідника |
| **Apromore** (open source/комерційний) | вебпрочес-майнінг | треба розгортати сервер або купувати хмару | ми: статичний сайт, нічого не розгортати |
| **Jira add-ons: Time in Status, Timepiece, Time Between Statuses** | звіти часу в статусах всередині Jira | платні за користувача на Marketplace | вони дають **таблиці**, ми даємо **карту процесу**: реальні шляхи, повернення, варіанти |
| **Jira control chart / cumulative flow** | вбудовані звіти Jira | безкоштовно, але плоско | вони не показують, *яким шляхом* ішла задача |
| **LinearB, Swarmia, Jellyfish** (engineering metrics) | метрики DORA, час циклу PR | платні SaaS, читають репозиторій на своєму сервері | ми: без доступу третьої сторони до коду |

**Ніша:** «безкоштовний, приватний, миттєвий» process mining для команд, які ніколи не куплять Celonis, і для професіоналів, яким треба швидко показати картинку без проєкту впровадження. Чесно: це ніша, сам по собі продукт навряд чи багато продасть 🔸. Його сила в **портфоліо та демо**, а потенційні гроші, якщо колись, у (а) платному Jira Forge-додатку з тією ж картою прямо в Jira, (б) консалтингу «аналіз вашого процесу за тиждень».

## 5. Обсяг MVP (3–4 тижні)

### Входить
1. **Імпорт**: drag & drop CSV / XES, вставка з буфера, автовгадування колонок + ручне зіставлення.
2. **Jira-конектор як CLI** (`npx process-xray jira --site x.atlassian.net --jql "project = ABC"`): тягне задачі та changelog статусів, пише `xray-log.csv`. API-токен лишається на машині користувача.
3. **Аналіз у Web Worker**:
   - карта переходів (directly-follows graph): товщина стрілок за частотою, колір вузлів за часом очікування;
   - повзунок «показати 50% / 80% / 100% шляхів», щоб карта не була «спагеті»;
   - топ-варіанти шляхів з відсотком кейсів;
   - повернення назад («23% задач повертаються з QA в розробку»);
   - час циклу: медіана і 90-й перцентиль, гістограма;
   - фільтри за атрибутами (тип задачі, виконавець, період).
4. **Анімація потоку**: кейси «біжать» по карті по часу. Головний «вау» для LinkedIn і відео.
5. **Три демо-набори**: публічний open source Jira-проєкт, публічний GitHub-репозиторій (PR), один набір BPI Challenge.
6. **Експорт** PNG/SVG карти і посилання «поділитися» з анонімізацією (імена і назви кейсів хешуються).
7. **Приватність як функція**: сторінка «як ми працюємо з даними» + індикатор «0 запитів до сервера» (можна відкрити DevTools і перевірити).

### Не входить у MVP
Розширення браузера, MCP, GitLab/GitHub/Linear у браузері, OCEL, порівняння двох періодів, conformance checking (порівняння з еталонною моделлю BPMN), акаунти, будь-яке зберігання.

### Наступні кроки після MVP (у порядку цінності)
1. Розширення браузера для Jira (Cloud і Server/Data Center) з тим самим кодом конектора.
2. GitLab + Linear прямо з браузера, GitHub PR через токен.
3. MCP-сервер «Process X-ray for Claude» з відкриттям карти за посиланням.
4. Порівняння «до/після» (наприклад, до і після зміни процесу погодження).
5. Вбудовуваний viewer (npm) + шаблони SQL для Camunda, OpenText, Kofax.
6. Можлива платна версія як Jira Forge-додаток (дані лишаються в Atlassian).

### Стек (попередньо)
Статичний сайт: TypeScript + Vite + React, обчислення в Web Worker, граф через ELK.js або dagre + SVG/Canvas, Papa Parse для CSV. Хостинг Cloudflare Pages або GitHub Pages. CLI на Node.js в тому ж монорепо з конекторами як окремим пакетом. Тести: Vitest, Playwright. (Відрізняється від дефолтного стека проєкту, бо тут немає бекенда й бази.)
